# 侧边栏的四条 WebSocket 连接说明

本插件一共开了四条 WebSocket 通道。它们干的是同一类事：服务端一有变化，马上告诉浏览器，让侧边栏不用傻等下一次定时刷新。

## 先说思路：推送负责"告诉你该看了"，能带答案就直接带

四条通道里有三条是纯提醒：连接推来的只是"该重新看了"，不带内容，内容照旧由对应的 HTTP 接口给出（fs-watch、sidechat、agent-opens 的读取接口各管各的）。

`/sidebar/ws/session` 这条更进一步：它的"工作目录"帧直接把答案带上了——宿主推的就是查询接口自己算出来的那份结果，两边永远不会不一致。这个会话的 5 秒定时轮询在连接打开期间整个暂停，断线了才自动恢复，当兜底用。

这样做的好处不变：连接断不断，都不影响侧边栏显示得对不对。断线时，侧边栏退回原来的定时刷新节奏，一切照旧，只是变化被知道得晚一点；连上之后，连"重新问一次"都省了，答案自己送上门。

## /sidebar/ws/agent-opens：模型主动打开东西

**解决什么问题。** 模型干活时经常想让你"看这个"。没有这条通道，它只能在聊天里贴个路径，你得自己复制、自己找到地方打开。有了它，模型可以直接把文件、文件夹或网页在你的侧边栏里打开。

**什么时候建立。** 侧边栏挂载、确定了当前会话就连上，一个会话一条。这个功能默认关闭，要在设置里打开"模型主动打开"开关。

**服务端推什么。** 模型的打开请求：要打开哪个文件、哪个文件夹或哪个网址。你此刻不在线也没关系（比如页面刚刷新），请求会在服务端等你，接上后立刻补送，不会丢。

**界面上发生什么。** 文件在侧边栏的编辑器标签里打开；文件夹打开一个以它为根的文件窗口；网址在侧边栏自带的浏览器标签里打开。

**与 HTTP 的分工。** 这条是纯投递，没有对应的查询接口——它送的是一个动作。打开之后显示什么内容，仍由编辑器、文件窗口、浏览器各自的读取接口负责，这条通道一概不管。

## /sidebar/ws/fs-watch：文件树自动更新

**解决什么问题。** 文件树是展开文件夹那一刻列出内容的，之后不管是谁改了磁盘——构建、格式化工具、模型执行的命令——树上看不到，得手动刷新。这条通道让树自己跟上磁盘。

**什么时候建立。** 文件树挂载就连上。侧边栏会告诉服务端自己展开到哪几个文件夹，服务端就只盯这几个目录；你收起了哪个，服务端就不再盯它。

**服务端推什么。** "某个目录的内容变了"的通知。只有目录，没有变动内容本身。

**界面上发生什么。** 对应文件夹就地重新列出：新文件补进来，删掉的就消失。构建跑起来的时候，你能看着产物一个个冒出来。

**与 HTTP 的分工。** 目录里到底有什么，仍由文件树原有的列目录接口回答。推送只负责说"这一层旧了，重新列一次"。

## /sidebar/ws/sidechat：侧边对话实时滚动

**解决什么问题。** 侧边对话的回答以前靠定时轮询，最长要等两秒才看到新内容。回答正在一个字一个字往外蹦的时候，这个停顿很明显。这条通道让侧边对话的节奏跟上主聊天。

**什么时候建立。** 侧边对话面板打开、有要跟的对话线程就连上；没有打开的线程就不连。每个打开的对话标签跟自己的那一条线程。

**服务端推什么。** "这条对话有新内容了"的提醒，只有对话标识，没有消息内容。回答流式输出期间，提醒会合并成一个稳定节拍，不会一个字一条地刷。

**界面上发生什么。** 刚发出的消息立刻显示已被接收；回答逐句出现；工具调用一结束，结果马上落进对话。整条对话看起来是活的，不是每两秒跳一格。

**与 HTTP 的分工。** 对话内容仍由侧边对话自己的事件接口给出，推送只负责"该去拉了"。拉回来的内容和顺序，跟以前是同一套，没有第二条数据来源。

## /sidebar/ws/session：会话相位翻转 + 工作目录实时答案（较新版本加入）

**解决什么问题。** 侧边栏关心两个会话级的事实。一，这个会话是不是还没说过话：空白会话里宿主不渲染会话头，插件得在输入区旁边放一个备用入口，等会话一开口，备用入口就该让位。二，这个会话实际在哪个目录干活：模型可能中途切到别的 Git 工作树，文件树和 Git 面板得跟着换根目录。这两个事实以前各靠一个定时轮询，最多慢一拍——备用入口可能晚一点才消失，新目录可能要几秒后才生效。

**什么时候建立。** 侧边栏要读会话相位或工作目录时就连上，跟着当前会话走。

**服务端推什么。** 两种帧。一是"这个会话不再是空白的了"，一个会话只推一次，因为空白只会结束一次。二是工作目录帧，带着答案：宿主在订阅时和每次工具调用（合并成 250ms 一拍）后，现场算出当前工作目录，直接放进帧里推过来；万一没算出来，就退化成只带会话标识的旧式提醒，客户端自己再问一次。

**界面上发生什么。** 发出第一条消息后，输入区旁的备用入口立刻消失，入口还给会话头；模型切了工作目录，新根目录在合并窗口后的一拍之内直接落地，文件树和 Git 面板马上按新根目录重新加载，不用等下一个刷新周期。

**与 HTTP 的分工。** 连接打开期间，客户端的定时轮询整个暂停，工作目录的答案全部来自推送帧（和原来的查询接口同一份实现、同一个答案）；断线时轮询自动恢复，加上挂载时的首次读取，断线兜底和以前完全一样。答案只有一处来源，推送只是换了一条更快的路送过来。

## 四条通道对照表

| 通道 | 一句话用途 | 你能感觉到什么 |
|---|---|---|
| /sidebar/ws/agent-opens | 把模型的"打开"请求送进侧边栏 | 模型让你看文件、文件夹或网页时，它们自己弹开，不用你复制路径 |
| /sidebar/ws/fs-watch | 文件树目录变更监听 | 树上的文件跟着磁盘实时变，产物冒出来不用手动刷新 |
| /sidebar/ws/sidechat | 侧边对话实时推送 | 回答逐句出现、工具一结束就出结果，没有两秒一跳的顿挫 |
| /sidebar/ws/session | 会话相位翻转 + 工作目录实时答案（较新版本加入） | 备用入口及时让位；模型切目录，新根目录一拍之内直接送达，断线才轮询 |
